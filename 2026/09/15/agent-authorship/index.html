Agent 替我做完之后

成品之外

假设我要给一个小装置做块电源板：十二伏输入、五伏输出，持续提供三百毫安电流，装进外壳后仍能稳定工作，温度也在允许范围内。把要求交给 Agent，最后拿到通过测试的成品，项目是否成功有据可查。难检查的是另一件事：项目结束以后，我自己发生了什么变化？

“这还算不算我做的”当然可以讨论。提出用途、制定约束、作出设计判断、执行操作和验证结果，可以分别讨论各自的贡献。但本文暂时把归属问题放在一边，转向另一个更难从成品上观察的问题：对于准备长期投入的领域，怎样在交付项目的同时，让自己的能力有所积累？

这里的电源板是一个假设案例。MCP 调用外部工具、Computer Use 操作软件界面，已有官方文档和使用说明；将这些能力接入设计、制造和测试，是进一步的技术推演。下面暂且假设，所需接口、授权和实物验证已经就绪，Agent 能可靠推进整条流程。这不是我已经验证过的自主制板系统，而是为了考察：当事情确实能被做好时，人的学习会怎样发生。

过去，做这块板子可能迫使我查器件资料、估算发热，再拿测量结果修正判断。操作本身不保证理解，但理解不足常会阻碍进度。Agent 可以接过这些判断，让任务越过我尚未弄懂的地方。项目因此得以开始和完成，这份收益是真实的；只是原本被进度要求带出来的学习，现在不一定还会发生。

因此，有三件事需要分别看：这块板子是否满足要求，是项目表现；我借助 Agent 能否处理更多、更复杂的任务，是人机系统的能力；在近似工具条件下，我是否更会发现问题、判断方案和安排验证，才涉及个人能力的变化。当任务能够绕过我的理解继续完成时，学习就需要成为工作流中被单独安排的一项任务。

学习发生的地方

Agent 接手的并不只有画图和查表，也包括发现问题的时机。假如它发现稳压器发热过大，换了器件、改好布局，最后给出完整说明，我可以读懂每一步，却没有练习过从异常中挑出线索、提出原因，再决定先检查什么。记录保存了问题的处理过程，但没有让我经历原先的不确定性。

这种差别也存在于错误经验里。自己估计过温度，后来发现偏差，才会知道原先忽略了什么；只看修正后的方案，则可能不知道一个看似合理的判断怎样失效。器件、负载与外壳之间的联系，也往往是在修改相互牵动时才变得具体。若这些往返一直由 Agent 处理，人得到的可能是一组正确结论，却缺少主动调用它们的线索。对初学者，这是某些认识尚未形成；对熟练者，才可能涉及已有技能的生疏。

更接近工程工作的证据来自 Shen 与 Tamkin 在 2026 年公开的编程实验。开发者用陌生的 Python 异步库 Trio 完成任务后，AI 辅助组在紧接着的掌握程度测验中表现更低，完成时间的差异则不显著。研究中的工具是对话式助手，并非自主执行整个项目的 Agent；它测到的是任务后的短期掌握程度，不能据此推断多年后的能力变化。

这些练习不必原样恢复。以前，遇到一个不懂的参数，可能要在资料里找很久，甚至就此放弃项目；现在可以请 Agent 针对当前方案解释，追问我的依据，或构造一个让这份方案失效的反例。反馈能更及时，也更贴近我正在犯的错误。省下来的操作时间，可以用于比较原先没有余力尝试的条件。

让电源板的条件变一次：输出电流从三百毫安增加到六百毫安，其余条件暂时不变。如果采用线性稳压器，忽略器件自身消耗的少量电流，损耗由（12－5）×0.3＝2.1 瓦增加到约 4.2 瓦。TI 的器件资料也明确将输出能力与散热条件联系起来。电流仍低于器件标称上限，并不足以说明原来的板子还能在同一外壳中持续工作；功耗翻倍也不等于温度读数简单翻倍。

这时，我可以先写下预测：哪些结论还能沿用，哪些需要重算，还缺少什么信息。再请 Agent 检查推理，比较改善散热与更换电源拓扑的代价，并指出需要实测的部分。若计算与测量不符，就区分是计算遗漏、模型假设不合适，还是测量条件不同，再据此修正判断。Agent 仍负责大量工作，但我经历了一次自己的预测被结果修正的过程。

教育实验提供了一些关于这种安排的证据。Bastani 等人的高中数学实验中，基础对话式 AI 提高了练习表现，却降低了撤去辅助后的测验表现；教师设计的提示大幅减轻了这一影响。Kestin 等人的大学物理实验则发现，经过教学设计的 AI 辅导，在两节课的即时测验中带来了比课堂主动学习更大的学习增益。这些场景都不同于工程 Agent，也不是长期追踪。它们提示的是：让工具交出答案，和让工具组织人的尝试与反馈，是可以分别设计的工作。

我想亲自判断的事

但如果工具长期可靠，我为什么还要花时间掌握这些判断？这个反对意见有道理。对于一次性、低风险、又不准备继续投入的任务，彻底委托可能就是合适的选择。我没有必要为了做一个小装置，先把电子、机械和制造都学一遍。人的注意力有限，保留所有旧技能，反而会挤掉更值得投入的事情。

我会看这种理解是否反复影响未来决策，判断错了要付出多大代价，外部帮助能否稳定获得，以及缺少它时，我能否发现 Agent 没有主动指出的问题。偶尔用到的封装尺寸可以现查；如果我经常给装置改供电，负载、损耗与散热的联系就值得掌握，因为它会影响我提出什么要求、接受哪些测试结果。工具越稳定，某些记忆和操作越可以交出去；留下来的能力，应当有具体用途。

即使 Agent 每次都能正确解决供电问题，理解这些联系仍可能改变我怎样构思装置：在确定尺寸以前就考虑散热，在增加功能以前就估计供电代价。它使我更早参与取舍，而不只是从几份已经完成的方案中挑选。当然，如果连这些取舍我也愿意委托，且依赖的代价可以接受，就没有必要仅凭“这是基本功”要求自己掌握。学习的理由需要来自我想长期参与什么。

尤其不能把“以后我负责把关”当成现成的答案。Bainbridge 在 1983 年的《自动化的反讽》中讨论过：系统接管日常操作，人却仍被要求处理异常，而日常练习的减少又可能使接手更加困难。这是工业控制中的分析，不是今天使用 Agent 的长期实验。它指出的矛盾仍然有用：如果我准备承担审查责任，就需要知道这种判断靠什么维持，不能只把最后一次确认留给自己。

对我而言，准备长期投入的领域，值得牺牲一部分即时效率，保留几次必须自己判断的机会。具体到这块板子，我愿意先估计一次功耗，说明为什么需要重测，或者比较一次更换拓扑的代价；文件整理和重复操作则可以充分委托。对一次性的边缘任务，我接受更彻底的代办。这是我对时间的分配，不是所有人都应遵守的学习纪律。

这份选择需要占用真实的时间。Agent 省下两小时，不代表我自然多了两小时学习；我也可能立刻多接一个项目，把空出来的注意力再次用完。因此，我更愿意在开始时选定一个要理解的问题，只在相关的判断处停下来比较和验证。要求每一步都讲解，既容易增加阅读负担，也未必能让我抓住最值得弄懂的部分。

下一次条件改变时

检验这种投入，不必突然拿走 AI，要求自己独立重做整块板子。工程能力本来就包含使用资料、仪器和他人的帮助。更有意义的是，在工具条件基本相同的时候，换一个没有练习过的约束，看看自己的判断有没有变化。如果模型升级后主动指出了更多风险，那首先是系统进步；我无法脱离它完成全部工作，也不能单凭这一点就说自己退化了。

回到负载增加的情形，如果 Agent 已经提醒“需要重新核算散热”，我能顺着解释复述二点一瓦变成四点二瓦，至多表明我跟上了这份说明。另一种变化是：尚未收到提醒，我就意识到原先的持续工作测试不再充分，主动要求检查新的热条件。能够复述答案，与能够发现答案的适用条件已经改变，是不同层级的能力。

还可以再换一个条件：电流保持不变，装置却要放到更热的环境里。此时，我是否会想到原来的温度余量可能不够？能否从笼统的“安全吗”，转向追问测试时的环境温度、散热条件与连续运行时间？面对仿真结果，我是否知道哪些假设需要核对、哪些结论需要通过实测独立验证？这些问题比记住上一次的数值，更能看出理解是否迁移。

问得更多也未必就是进步。一个问题若能区分“器件额定电流不够”和“散热条件不足”，并据此改变下一步检查，就比请 Agent 再做一次全面检查更能说明判断有所发展。我仍然可以让它查数据、做计算；变化在于，我更清楚为什么需要这些信息，以及不同结果将怎样影响决定。

一次答对仍可能只是刚看过解释。隔一段时间，在另一个装置上遇到相似关系，能否再次主动发现，才更值得参考。我可以留下最初的预测、后来改动的理由，以及下一次需要多少提示才能意识到问题。不必把每个项目变成考试，但如果只记录成品和 Agent 的总结，就很难看清自己的变化。

项目结束以后，我更想换一个条件，再看一次：有没有什么问题，是项目开始之前的我不会主动发现，而现在会让我更早停下来，重新判断？
