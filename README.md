# 海果不能吃

Homalozoa 的个人博客。随笔、Linux 与机器人。英文名为 “Homalozoa is not for eating.”。

界面取意于《无人深空》的星际风景：青灰天空、赭红峡谷、象牙白行星和细线导航。首页使用原创风景图，文章与归档延续深青底色和暖白文字。正文、原始日期、永久链接及标题锚点保留；2021 年的技术文章仍是当年的记录。

## 本地开发

需要 Node.js 20 或更高版本，无 npm 依赖，无需安装。检查脚本使用 Python 3 标准库。

```sh
npm run dev
```

打开 http://127.0.0.1:4173。开发服务器仅监听本机，仅提供公开页面与静态资源，不暴露 Git 和源文件。服务器启动时自动生成页面；修改模板或文章后运行 `npm run build` 并刷新页面。修改 CSS 或浏览器脚本后直接刷新。

```sh
npm run build
npm run check
```

检查涵盖所有页面、站内路径、标题锚点、字体与图片引用、历史正文和时间信息的保留情况。

## 本地网页编辑器

```sh
npm run editor
```

打开 http://127.0.0.1:4174，进入「写作室」。无需安装依赖，服务只监听本机。端口占用时可运行 `BLOG_EDITOR_PORT=4175 npm run editor`。

- 点击「写一篇新的」，填写标题和正文。工具栏支持标题、加粗、斜体、引用、列表、链接、图片和代码块；HTML 按钮切换正文源码。
- 草稿在停止输入约 0.8 秒后自动保存到 `.local/editor/drafts/`。该目录被 Git 忽略，不进入博客构建；重启编辑器后可以继续写。`⌘S` / `Ctrl+S` 也可保存。目录没有云端备份，可用「导出草稿」下载 JSON，再通过「导入」恢复。也支持导入 HTML 和纯文本。
- 在「文章设置」中填写网址标识、发布时间（UTC+8）、分类和摘要。「对照预览」使用当前网站样式，也可切换手机宽度或单独阅读。
- 在「站点文章」中选择已有文章，修改会先存为本地草稿。原有文章的发布时间和永久链接保留。
- 图片先放入 `assets/images/` 或 `images/`，再用图片按钮填写 `/assets/images/文件名.webp` 等路径与说明文字。
- 点击「写入并提交」后，编辑器先在临时目录生成文章并运行现有构建与检查；通过后更新 `content/posts.json`、正文和生成页面，再使用本地 Git 配置创建 Conventional Commit 和 GPG 签名，并验证签名。仅提交当前文章及其生成页面，其他已暂存文件保留原状。
- 提交成功后，草稿移到 `.local/editor/trash/`，左侧不再显示为待写草稿。需要找回时切到「废纸篓」，点击对应草稿即可恢复；文章仍可从「站点文章」继续修改。内容已经提交且没有变化时，不重复创建提交。
- 在「文章设置」中可选择「仅写入本地站点」，保留草稿、稍后手动提交；也可把草稿手动「移到废纸篓」，该操作不删除站点文章。
- 检查、提交或签名验证失败时保留草稿并显示原因。签名提交失败时，本地站点修改也会保留，修复签名配置后可重试。若其他文章、模板或资源有未提交修改，或站点文件已经暂存，会先提示单独处理，避免混入当前文章的提交。
- 写入后打开提示中的本地文章链接检查完整页面，再按原流程推送发布。编辑器不执行推送；本地签名提交成功不表示线上部署完成。

编辑器独立于 `npm run dev`；普通预览服务不提供草稿或写入接口。编辑器的写入接口要求同源 JSON 请求，并检查主机名。富文本编辑仅显示静态 HTML，预览在禁用脚本的 iframe 中运行。切换到富文本并修改时，会规范化 HTML；对必须精确保留的旧源码，使用 HTML 模式编辑。

检查编辑器：`npm run check:editor`。测试在临时副本中验证草稿持久化、跨源请求拒绝、链接错误时不改动站点、文章写入与固定链接保留，以及签名提交、无关暂存的保留、签名失败后的重试和废纸篓恢复。签名测试使用当前仓库配置的 Git 身份和可用 GPG 密钥，不修改真实文章或真实 Git 历史。

## 写作与维护

- `content/posts.json`：文章标题、摘要、分类、日期与永久链接。首页、归档与文章页使用相同标题；分类按钮由现有文章自动生成。
- `content/posts/*.html`：文章正文。保留 HTML 源码可以完整迁移原有代码高亮，无需重新安装旧主题。
- `scripts/build.mjs`：公共模板、引文、首页、文章页、按年/月归档及 404 页面生成。
- `assets/site.css`、`assets/site.js`：响应式样式、分类筛选、目录、代码复制与阅读进度。
- `assets/images/`：本地 WebP 风景图及生成说明。
- 根目录、`2021/`、`2026/`、`archives/` 中的 HTML：可直接发布的生成结果，请通过源文件修改并重新生成。

新增文章时，在 `content/posts/` 中创建与 `slug` 同名的 HTML，将文章信息添加到 `content/posts.json`（最新在前），运行构建与检查。`path` 填写以 `/` 开头和结尾的永久链接；`published`、`modified` 使用带时区的 ISO 8601 时间。正文顶层标题使用 `h2` 并设置唯一 `id`，即可生成目录。

首页与归档的分类筛选采用渐进增强：禁用 JavaScript 时显示全部文章。文章目录使用原生 `details`；手机初始收起，桌面初始展开。代码可以横向滚动，复制失败时提供手动选中方式。入场动画只播放一次，遵循 `prefers-reduced-motion`；打印时隐藏导航与装饰并切换为浅色正文。

## GitHub Pages

继续兼容原来的分支根目录发布方式：GitHub 仓库的 Settings → Pages → Deploy from a branch，选择 `main` 和 `/ (root)`。根目录 `.nojekyll` 允许直接提供静态内容，不需要 Hexo、Jekyll、GitHub Actions 或运行时服务。

发布时将修改后的源文件和构建结果一并提交，再推送至仓库。当前页面始终使用 `https://homalozoa.github.io` 作为 canonical 地址。代码变更本身不会自动推送或发布。
