假如我想给一个小装置做块电源板，把要求交给 Codex，随后拿到可以工作的电路、合适的外壳，以及制造和测试的结果，我当然会高兴。这件事过去可能要查很久资料，反复修改，甚至因为某个不熟悉的环节一直没有开始。现在，它做成了。但如果这样的项目连续做上半年，再回头看，变化的会只有桌上的东西吗？我对电路、材料和制造懂得更多了，还是主要获得了一种随时调动外部工具与知识的能力？

我越来越觉得，“这是我做的”里面最值得追问的，是后面这个问题。作品的来历可以交代清楚：哪些工作由我完成，哪些借助了 Agent。但这些协作也会改变以后的我。眼前的任务完成得更快、更好，并不意味着知识、经验和判断力会随之增长。要知道自己从 Agent 那里得到了什么，得同时看这一次完成了什么，以及连续这样工作之后，自己会变得更擅长什么。

就从这块小电源板说起：十二伏直流输入，五伏输出，给装置供电，还要装进外壳。手工制作时，画图、转印、蚀刻、钻孔、焊接常常由同一个人完成；后来有了电子设计软件与工厂的分工，许多加工动作可以交出去，但器件为什么换、尺寸为什么改，通常还要由设计者处理。亲自制作并不保证理解所有原理，却会让一些问题反复回到面前。器件资料里的一个参数，经过计算、尝试与测量，才逐渐与实际结果联系起来。经验往往就在这些来回里形成。

Codex 则可以进一步接手这些往返中的工作。它可以通过 MCP 调用外部工具、取得数据，也可以通过 Computer Use 查看和操作软件界面。这两种能力，使一项任务能够跨越多个应用，而不必每一步都等人手动转交。MCP 官方文档、Computer Use 官方文档 对电路设计而言，在接入相应的设计软件、能够读取元件资料并调用所需工具后，可以把原理图设计、元器件选型、布局布线与仿真放进同一项工作，让 Codex 连续推进。它的角色因此可以从回答设计问题，扩展到实际操作设计工具。

这条工作链还可以往外延伸。板子太大，就同时调整元件安排与外壳；希望降本，就比较替代器件、加工和装配方案，而不只寻找单价最低的零件。一个便宜的稳压器若增加了散热和结构成本，整套装置未必更便宜。三维外壳模型确定后，再通过已接入的切片、打印服务或工厂系统，在授权范围内把任务交给 3D 打印机或相应工厂。这是把 Codex 与相应工具、真实报价和制造条件接起来之后，可以组织的工作方式；具体能自动完成到哪一步，仍取决于这些连接和任务本身。软件操作成功，也不能代替装配与实测成功。

不妨就设想这块板子的流程已经接通：设计端与生产端能够交换问题，Codex 根据反馈修改方案，再依据试制结果继续调整。人仍然需要提供实际用途、必要条件和授权，但不必亲自处理每一次器件替换、尺寸修改与文件交接。对于下面的讨论，关键是让这个任务顺利完成。我们要看的，恰恰是当系统能把事情做好的时候，原本伴随制作而来的认识过程，会发生什么变化。

这需要把知识、经验和能力稍微分开来看。知道稳压器为什么发热，是对原理的理解；做过预测、看过温度随负载变化、修正过自己的估计，是在积累经验；面对一个新的装置，能用已有认识和可用工具把供电问题处理好，则体现了能力。三者会相互促进，但不能仅凭一次成功交付，就认为它们都已经增长。Codex 可以替我算出结果，保存完整记录，并让这块板子工作，但其中哪些内容成为了我的认识，还要看我怎样接触和运用它们。

以散热为例。采用常见的线性稳压器，从十二伏降到五伏，在三百毫安输出电流下，先忽略器件自身消耗的少量电流，稳压器需要持续散热，热功率约为二点一瓦。它会升到多高的温度，还取决于器件、安装和周围环境。TI 的 LM7805 系列资料将散热条件与输出能力放在一起说明。器件资料 因而，线路连接正确，未必意味着装进外壳以后可以持续工作。需要把负载与散热条件带进来，才能决定现有方案是否合适。

短期内，Codex 最直接的帮助，是让我越过一些原先卡住项目的地方。我不熟悉某类器件，它可以查资料、做比较；我不熟悉外壳建模，它可以操作工具，先做出一个能讨论的版本。原先只能想象的装置，变成了可以拿来试用的东西。对于初学者，这尤其重要：没有 Agent，另一种结果可能是项目一直没有开始，而非经过充分学习以后独立完成。先得到一份具体方案，也可能让我第一次有机会理解板厚、接口位置和散热之间的联系。

这种实现能力是真实的。人本来就借助手册、软件、工厂和他人的知识工作，不需要把所有本领装进自己的头脑，才算能够做事。Codex 能把这些外部能力更紧密地组织起来，我也就可能自己推动一个过去需要多人配合的项目。变化首先发生在“我能完成什么”上：能处理的环节多了，尝试一种想法的成本低了，原先不敢碰的部分也有了入口。把这些收获只看成一种错觉，会低估工具带来的自由。

但这份自由也带来一个容易忽略的时差：事情已经做成，我的理解可能还没跟上。读到“热功率约为二点一瓦”时，我可能觉得解释很清楚；但下次负载增加时，我未必会主动想到重新检查散热。前者可能只需要顺着一份说明读完，后者则需要把这次的原理带到新的条件里。短期内，方案完整、解释流畅、检查结果齐全，很容易让我觉得自己已经掌握了整件事。可交付的完整程度，并不能单独说明我的认识到了哪里。

学习研究中已有这类分离的例子。Bastani 等人在 2025 年发表的一项高中数学随机实验发现，学生使用基础对话式 AI 时，练习成绩提高；随后撤去辅助，独立测验表现却低于没有使用它的对照组。加入教师设计的提示、避免直接给答案后，这种负面影响大幅减轻，但独立测验成绩并未显著高于对照组。研究原文 这不能证明 Codex 会削弱设计能力，也不是多年后的追踪结果。它能支持的提醒是：有辅助时完成得更好，不等于自己学会了更多，两者需要分别观察。

对设计者来说，这种差别如果不断重复，就可能产生长期影响。假如每次都是 Codex 找出问题、分析原因、修改文件，我主要阅读最后的总结，那么练习得最多的，可能是如何提出任务与接收交付。电路调整的原因与代价，也就越来越少需要由我亲自权衡。对已经熟悉电路的人，这可能使某些不再使用的技能逐渐生疏；对刚开始的人，则可能是项目做了不少，某些基础认识始终没有形成。两种情况不同，不能都笼统称作“能力退化”：前者关乎已有本领的维持，后者关乎本领能否从一开始建立。

经验也可能随之发生变化。系统里保存了十次成功修改的记录，不等于我经历过十次判断与修正。如果我只看到了最后采用的方案，就可能不知道哪些做法曾经接近可行，哪些条件一变就会失效。那些未被采用的方案，原本也能帮助人理解边界。长期只接触整理好的结果，我可能越来越熟悉“正确答案长什么样”，却不太熟悉“一个答案怎样从不确定变得可信”。这是一种值得担心的可能：项目数量增加了，用来应对陌生条件的经验却没有按同样速度积累。

这种担心在更早的自动化讨论里就出现过。Lisanne Bainbridge 在 1983 年的《自动化的反讽》中指出，把日常操作交给系统、把异常留给人处理，会产生一个困难：人平时减少了练习，却仍被期待在发生异常时接手。论文原文90046-8) 这篇论文讨论的是工业控制，并没有研究今天个人使用 Codex 的情形。不过，回到这块板子，同样的问题值得提出：如果我把判断的日常练习交了出去，以后是否仍有足够的经验审查更复杂的方案？把最后确认留在人手里，并不会自动保留完成确认所需的本领。

但长期影响也可能朝另一个方向发展。Codex 能代办中间步骤，也能把原先很难完成的比较清楚地呈现出来。以前，我的时间和经费可能只够尝试一种方案，成功后便没有余力再试；现在，可以在合适的仿真模型中比较几种器件和布局，再挑出需要实物验证的部分。外壳厚度、元件位置、装配方式怎样影响结果，也更容易放在同一个项目里讨论。对于愿意理解这些联系的人，工具省下来的劳动，可以换成更丰富的观察，而不只是更多成品。

关键在于，这些观察是否进入了自己的判断。比如，下一次给装置增加负载前，我先估计散热负担会怎样变化，再请 Codex 检查依据，安排合适的计算和测试。结果与预计不同，就一起找出遗漏的条件。这里的学习仍然借助工具，却包含了我自己的预测，以及预测被结果修正的过程。仿真可以帮助比较，但仿真采用了哪些材料参数和环境假设、哪些结论还需要实测，也成为了讨论的一部分。这样积累的经验，不要求每个孔都亲手钻，却能让我下次更早认出同类问题。

AI 促进学习也有具体证据。Kestin 等人在 2025 年发表的一项大学物理随机实验中，比较了经过教学设计的 AI 辅导与课堂主动学习；在研究涉及的两节课里，接受 AI 辅导的学生，课后即时测验成绩相对于课前的提升更大。系统采用了分步引导、教师准备的内容与针对性反馈。研究原文 这同样不能证明长期设计能力会提高，但它说明，替人完成任务并不是 AI 唯一能支持的交互方式。让人尝试、回应具体困惑、帮助修正理解，也可以成为工具工作的内容。

如果这样的协作长期持续，设计者还可能逐渐具备跨领域处理问题的能力。我也许仍不擅长手工布线，却越来越懂得电路与外壳怎样互相限制；不熟悉每一种加工设备，却能更早想到装配、维修和成本之间的冲突。降本就是一个例子：从只比较元件单价，到会追问替代器件是否增加散热、结构或装配成本，是一种认识上的进展。Codex 把几个领域的资料与方案放到一起，能够给这种进展提供机会。它既可能替我处理复杂性，也可能帮助我逐渐理解复杂性。

不过，这种跨环节的判断也需要积累。要在需求里提前说明外壳与散热的条件，得先知道它们可能影响供电；要理解一份成本比较，又得看出哪些成本被计入、哪些还没有。减少具体操作，并不自动带来这些认识。因此，“以后我负责提需求和把关”描述的是一种分工，还没有回答怎样获得相应能力。Codex 也可以帮助整理需求、发现冲突，甚至提醒我原来的目标不合适。我们仍要继续追问，在这些帮助之下，我的判断怎样形成，又怎样通过下一次使用得到检验。

所以，长期的乐观与悲观并非只能二选一。同一个人可能更能推动完整项目，同时对某些电路细节更生疏；也可能减少了重复操作，却更擅长比较方案、发现跨环节的问题。能力不是只有一个总分。要判断变化，可以看下一次出现新条件时，自己能否意识到旧结论已经不适用，能否说明缺少什么信息，并借助合适工具找到答案。判断这种变化时，我仍然可以查资料、使用 Codex。考察的是我与工具怎样应对变化，而不是突然拿走所有帮助，再把独自完成当成唯一标准。

影响长期变化的，也不只是个人够不够好学。假如我把省下的时间全部换成更多交付，即使每份记录都很完整，也很难逐一消化。过去一周只做一块板子，如今同时推进几个装置，注意力不会跟着项目数量自动增加。而如果我有意留出时间参与一次重要取舍，让 Codex 展示方案之间的差别、检查我的预测，再把实测结果带回来，同样的工具就能服务于另一种积累。追求更快、更多的交付，会与深入理解争夺有限的时间，不能只用一句“保持思考”就略过其中的取舍。

这意味着，使用 Agent 时，我实际上也在安排自己的练习。需要迅速完成的部分，可以交由已验证可靠的工具和流程处理；希望长期理解的部分，则值得保留预测、比较和验证的机会。对于这块电源板，我未必需要重新练习所有制板工艺，却可能希望以后看到输入电压、负载或外壳变化，就会想到散热条件也要重新考虑。这个愿望足够具体，可以直接作为我与 Codex 协作的要求：不仅把板子改好，也让我有机会形成下一次会用到的认识。

至于哪些旧本领值得保留，也应当允许答案改变。如果某类工具长期可靠、随时可用，把部分记忆与操作交出去，本来就可以使人腾出精力。但“这项本领已经不值得投入”，与“我在没有留意的时候逐渐失去了它”，毕竟是两种过程。前者包含对用途、依赖和代价的判断，后者可能要等条件改变才被发现。我不需要成为一座自给自足的工厂，却有理由知道自己的能力依托哪些帮助，在哪些地方能够自行判断，又准备在哪些地方继续借助它们。

再回到桌上已经完成的装置，电源板稳定供电，外壳也合适。我可以说“这是我做的”，并讲清 Codex 参与了什么。但更值得继续问的，是下一次面对不同的负载、预算或制造条件，我会比这一次多看见什么。短期内，Agent 可以让作品先于我的熟练出现；长期里，它又会改变我经常接触的问题、反复练习的判断，以及逐渐不再使用的本领。作品完成得怎样，终究只是其中一半。另一半是，长期这样工作，我会成为一个怎样的设计者。
